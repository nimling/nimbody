# Changelog

## Unreleased

1. `state`: export and import of a service's data through `GET /state`, `POST /state/export` and `POST /state/import`: a schema document with field flags, NDJSON state lines with a manifest and a hash per group, export by filter and key, upsert, create and sync imports that map keys to ids and converge on a second run, deletes by key, dry runs, per record results over the step stream, and stored snapshots.
2. `cli`: `StateCommand` adds `state`, `state export` and `state import` to a cli and its mcp tools.
3. `state`: field flags are JSON pointers, `/config/client_secret`, found through nested `properties` and through `oneOf`/`anyOf` with a `discriminator`; `fields.sensitive`, `immutable` and `server_default` in `GET /state` now hold pointers where they held top level names. Export strips exactly the flagged pointers and never the object around them; immutable and server default checks on import work by pointer.
4. `state`: `Group.Discriminator` and `Group.Sensitive` declare the secrets of each type; `GET /state` publishes them as `fields.discriminator` and `fields.sensitive_by`, and export strips each record by its own type as well as by the schema flags.
5. `terraform`: every cli that registers it is its own Terraform provider. Started by Terraform it serves each state group as `<provider>_<group>`, with read by key, create and update as an upsert import, delete by key and a dry run in the plan; secrets are write only and sensitive per pointer and per type, immutable fields force replace, server defaults are optional and computed, and references are keys. `<cli> terraform install` places the binary in the local plugin directory or a filesystem mirror, at the cli's version.
6. `cli`: `Provider` and `EnvTerraform`, the hook `Execute` serves the provider through when `TF_PLUGIN_MAGIC_COOKIE` is set; `terraform` joins the tooling commands that are not mcp tools.
7. Module: `hashicorp/terraform-plugin-go` v0.30.0 and what it brings, grpc and protobuf among them, imported only by `terraform/`; `stretchr/testify` to v1.10.0 and `golang.org/x/net`, `crypto` and `text` raised by it.
8. `terraform/registry`: the running service is the Terraform registry of its own provider and modules. `Mount` serves `/.well-known/terraform.json`, the Provider Registry Protocol under `/terraform/providers/v1/samna/<cli>/` with versions, platforms, the download with its `SHA256SUMS`, signature and the org public key, and the Module Registry Protocol under `/terraform/modules/v1/samna/<module>/<system>/`, exactly at the version the instance runs. Files stream through the instance from the repo's GitHub release with the read token the host's `Release.Token` hook answers; a release that cannot be read answers 502.
9. `terraform/registry`: an optional http state backend at `/terraform/state/<workspace>` with `LOCK` and `UNLOCK`, 423 with the held lock on a conflict, behind the host's access middleware and over the host's storage callbacks.
10. `terraform`: `<cli> terraform package` writes the release files, a zip per platform, the `SHA256SUMS` to sign and a tar.gz per module in `deploy/terraform/<module>/<system>/`; the provider namespace defaults to `samna`.
11. `endpoint`: `Mount` with a `Set` mounts the common endpoint set, `/status`, `/status/health`, `/state`, `/mcp` and the Terraform registry, beside the service's own `/api`.
12. Module: `golang.org/x/crypto` is a direct requirement, for the test of the signed sums under `test/` only.
13. `cli`: `config set --config <name> key=value` creates a named config that does not exist yet, as the refusal's hint says; `Load` no longer refuses the unknown name for that one command, and every other command still refuses it with the same message and hint.
14. `respond`: a route declares the largest step stream frame it sends with `FrameLimitMiddleware(bytes)`, `0` for unbounded, and every stream announces it in the `X-Frame-Limit` header; a route that declares nothing announces `FrameLimit`, 16 MiB, as before. `stream.Read` sizes its line scanner from that header, so a result frame over 16 MiB no longer fails with `bufio.Scanner: token too long` where the route allows it. `POST /state/export` declares an unbounded frame, so a streamed export with blobs reads whole.
15. The step stream frame limit reaches the mcp path. `/mcp` announces `X-Frame-Limit` from the operation it calls, `stream.Scanner` is the one reader sized from that header, and the stdio bridge reads the service's `/mcp` stream through it, so a `state_export` result over 16 MiB passes `<cli> mcp`. The `state_export` tool declares the unbounded frame its route does. `mcp.Exec` reads the cli's own stderr without a fixed cap. The lines a host sends on stdin to `<cli> mcp` stay capped at 16 MiB, as no endpoint has answered when they are read.
16. `cli`: typed mcp tool input. A command tree whose root, or any command above a leaf, carries `AnnotationMCPInput: InputTyped` gets one input property per flag and per positional of the usage line, typed boolean, integer, number, string or array, with the required flags and positionals listed; an `id` positional is named for its parent, `article_id`. Without the annotation the tools keep the `{args, flags}` input as before, and a typed tool still accepts a call in that shape. `mcp.Flag` gains `Positional` and `Required`, `mcp.GetInputSchema` builds the typed schema.
17. `cli`: a flag a `Setting` marks `Secret`, or a flag annotated `AnnotationSecret`, never appears in a tool's input schema; `Settings.Flags` records the secret flags on the root.
18. `cli`: `PutOutput[Out]` declares a command's output struct. Its tool carries the `outputSchema`, `{data: <schema of Out>}` as `/mcp` tools do, and a stdio call answers `structuredContent` `{data: …}` from the json the command prints, unless the call shapes the result with `fields`, `sort`, `jq`, `template`, `raw`, `plain` or `format`. `mcp.GetOutputSchema` is the exported schema builder `Define` uses.
19. `mcp`: a destructive tool carries `_meta["anthropic/requiresUserInteraction"]: true`, `MetaUserInteraction`, on stdio and on `/mcp`; a tool's `_meta` is merged with its page link instead of replaced.
20. `mcp`: `Server.Instructions` is answered in `initialize`. `cli.MCPCommand` sends `GetInstructions(root, name)`, the root's `AnnotationMCPInstructions` or a few lines made from the root's `Short`.
21. `mcp`: `Spec.Example` is the example of an operation: `cli.OperationCommand` sets it as the command's `Example`, and the operation's tool appends it to its description through `Describe`, which caps a description at 4096 characters with the confirmation note.
22. `cli`: the credential store every api cli copied, on `Settings`: `GetCredential`, `GetCredentials`, `PutCredential`, `DeleteCredential` and `LockCredential` keep one login per host in `~/.<cli>/<host>.cred` and one machine token per host and client in `<host>_<client>.client`, with the keys the copies wrote, so a stored login carries over. The tokens live in the OS keychain through `Keychain`, `security` on macOS and `secret-tool` on Linux, with only the metadata and `<PREFIX>STORE=keychain` in the 0600 file; where no keychain answers they stay in the file. `LockCredential` is the cross process lock a refresh or an exchange holds.
23. `cli`: `Settings.Get(key)` answers a key's resolved value, a secret unmasked, from the layers `Load` read.
24. `cli`: `Client` is the shared api client and login. Its credential is `<PREFIX>TOKEN`, or `<PREFIX>ACCESS_TOKEN`, from the environment for CI, else the stored login, refreshed before expiry under the lock, else the machine pair `client_id` and `client_secret`, sent as Basic auth to the service on every request. A client whose service issues tokens sets `Exchange` to the path that does and exchanges the pair for a token instead, cached under the lock until 30 seconds before expiry, so parallel runs share one token, and exchanged again once when the service refuses it. `Send` is a `Send`: it reads the step stream, reports steps on stderr, names itself `<cli>/<version>` or `<cli>/<version> (mcp)`, and maps a status to the family exit codes with a hint.
25. `cli`: `Client.LoginCommand`, `LogoutCommand`, `StatusCommand` and `TokenCommand`: PKCE with a loopback callback, `--no-browser` with a pasted code, the session exchanged and refreshed at `TokenPath` and revoked at `RevokePath`, the identity from `IdentityPath` and the health from `HealthPath`, `/status/health` unless set. The cli names `LoginPath`, `TokenPath`, `RevokePath`, `IdentityPath` and `AppHeader` itself; nimbody carries no default for any of them, and `Client.Mount` and `login` refuse a client that leaves one out, naming each. `OpenBrowser` is the hook that opens the address.
26. `cli`: a default `Bridge`. `Client.Mount` validates the client, adds the four commands and, when the cli set no `Bridge`, makes `Client.Remote` the bridge: `<cli> mcp` relays to the service's `/mcp` with the stored credential when `GET /status` lists `/mcp` and the credential is a bearer token, and serves the tools locally otherwise, a Basic machine pair included.
27. `cli`: `Body` is the body flags every api cli copied: `--set key=value` repeated with dotted nesting and json values, `--data '<json>'`, `--file <path|->`, and `--upload <file>` for a multipart file part with the `--set` entries as form fields. `Body.Get` answers the bytes and the content type, and refuses `--data` with `--file` and a `--set` without `=`, exit 2.
28. `cli`: `APICommand(send, output)` is `api <method> <path>` with the body flags, for anything the resource table does not model. The method sets the command's access, so a `GET` is a read a protected config does not ask about; an unknown method or a path without a leading slash is refused, exit 2. `Client.Mount` adds it.
29. `cli`: `Table` builds the resource commands from a declaration: each `Resource` with its `Verbs` and `Children`, a verb's `Paths` indexed by how many ids it takes, `{name}` placeholders positional in path order unless `Fill` answers them, the access from the method unless `Access` says otherwise, the body flags where `Body` or `Upload` is set, and an `Example` per command, one line per arity, unless the verb sets its own. `Mount` adds every resource and a hidden top level shortcut for a child name used once.
30. `cli`: `Output.Format`, `--format concise|detailed`: concise keeps the leading scalar columns of a list, as the table picks them, and the scalar fields of an object; detailed, the default, keeps everything. `Output.Query`, `--query key=value` repeated, passes the server's own filters through `GetQuery`. A `--query` without `=` or another `--format` is refused, exit 2. Both flags come with `Root`; `Output.Flags` keeps its set, so a cli that defines `--query` itself still starts.
31. `cli`: `config get` and `config list` print json when the command's `--json` flag is set, on a terminal too.
32. `cli`: `HelpCommand(banner, document)` is the shared `help`: with no topic it prints the bundled SKILL.md without its frontmatter to stdout, headings styled and the banner first only on a terminal; `help <command>` is that command's help, an unknown one exit 2. `HelpFunc(banner, base)` prints the banner above the root's help only on a terminal.
33. `cli`: `Root(root, settings, output)` mounts `Settings` and `Output` on the root, with `--format` and `--query`, typed mcp input, silenced cobra errors, and a `PersistentPreRunE` that loads the settings and guards the write before the cli's own hook, so a cli cannot skip either.
34. `cli`: `Root` refuses a `Setting` that is `Secret` and names a `Flag`, at start, since a secret is never a flag; `Settings.Flags` alone still takes one, so a cli that has not moved to `Root` keeps its flag.
35. `cli`: `--plan` stops `config set`, `config use`, `config init` and `config local` too: each prints the write it would make, a secret masked, and exits 0 without touching a file.
36. `cli`: the `config set` example writes a named config with `--to`.
37. `cli`: `CompletionCommand(root, skill)` is the shared `completion [shell]`: it prints the script for one shell, or with `--auto` detects the shell from `$SHELL`, writes the script under the XDG data dir, `$XDG_DATA_HOME/<cli>/completions` or `~/.local/share/<cli>/completions`, and keeps one managed block in `~/.zshrc` or `~/.bashrc`; fish gets its own completions directory. `--skill` installs the bundled skill in the same step. It turns off cobra's default completion command. `GetDataDir` answers the data dir.
38. `cli`: `cli.Version` is the one ldflags symbol, `-X github.com/nimling/nimbody/cli.Version=v1.2.3`; `GetVersion` answers it, or the module version a `go install …@version` build carries, or `dev`.
39. `cli`: `VersionCommand(server)` prints `{version, server}`, the server's from the function given, `Client.GetServerVersion` reading `GET /status` for an api cli and nil for a tool cli; an unreachable server is a warning on stderr, never a failure.
40. `cli`: `Notifier` is the update notifier. `Mount` checks `Latest` at most once per `Every`, a day by default, cached in `~/.<cli>/update.json`, and prints a note on stderr after the command when a newer version is out, only on a terminal and never under mcp or for a `dev` build. `<PREFIX>NO_UPDATE_NOTIFIER` turns it off. `Newer` compares two versions, a release above its prerelease.
41. `cli`: `--set key=@path` reads the value from a file, then decodes it as json when it parses, as every other `--set` value; in a multipart upload the file's content becomes the form field. An unreadable file is rejected.
42. `mcp`: `Spec.Status` is the success status of an operation on the route, `200` on a `POST` that runs, tests or checks, `202`, or `204`, which answers no body, or the result frame alone on a step stream. Left at `0` it stays `201` on `POST` and `200` on every other method.
43. `mcp`: `Spec.Paths` are further paths one operation answers on beside `Path`, so a cli `get [id]` is one tool over `/sources` and `/sources/:source_id`. `Route` mounts every path; a tool call takes the path whose placeholders are all given, the one with the most when several are, and answers `<name> needs <input>` as an error when none is, where it used to call the service with the placeholder left in the path. A path input is required only when its placeholder is in every path. `cli.OperationCommand` takes the optional positionals, `get [source_id]`, and picks the path by how many are given.
44. `mcp`: open query keys. A `map` input tagged `query:"var.*"` holds every query key under the prefix, `var.region=eu` as `region: eu`, and `query:"*"` every key no other query input declares, outside `limit`, `page`, `order`, `column` and `cursor`. The route fills the map from the query and a tool call sends each entry as a query key, so the keys reach the service's input and `ctx.QueryParams()` on both transports; `cli.OperationCommand` takes them as a repeated `--<name> key=value`.
45. `respond`: `Rejection` is the error a service function returns to decide what both transports answer: `Status`, `Message` and `Data`. The route answers `respond.Error` with them, the data as the envelope's `data`; the tool answers `isError` with the message as text and the data as `structuredContent` `{data: …}`. A middleware that refuses a tool call with error data carries it the same way. `*echo.HTTPError` still answers its code and message, and any other error still answers `Internal server error` on the route and `the server failed on <name>` on the tool, logged.
46. `mcp`: `Spec.Invalid` is the message a bind failure answers, `400` on the route and `isError` on the tool; left empty it stays the binder's text.
47. `mcp`: an input tagged `header:"<Name>"` is a request header. The route binds it, and a tool call sets it on the request before `Spec.Middleware` runs, as it sets each path input as a path param, so a middleware that reads the app slug from `SAuth-App-Slug` or the `app_slug` path param sees a tool's `app_slug` input exactly as it sees the route's. `cli.OperationCommand` makes no flag for it, since the cli's client sends its own headers.
48. `mcp`: `Spec.Middleware` is the whole chain of an operation on both transports. `Route` mounts it on each path and a tool call runs it inside `/mcp`, so a service mounts its operations with `Route` on a group that carries no middleware of its own, `e.Group("/api")`, and nothing runs twice on the route or on one transport only. `endpoint.Set.MCPAccess` stays the gate of `/mcp` itself, for every method, `tools/list` included, and runs before the operation's chain.
49. `mcp`: the route binds the body first, then the query, the headers and the path params last, so a path param always wins over a body key of the same name; it used to be overwritten by the body. Query inputs are bound on every method that declares one, as a tool call always sent them; before, only on `GET`, `DELETE` and `HEAD`.
50. `mcp`: an answer that is not JSON, a blob, a file download, a redirect or a multipart upload, stays a plain route beside the operations, and the operation whose JSON answer it shares is called from that handler, as `samna_sync` serves the zip of `mapper_export`. A tool result is text and structured JSON, so such a route has no tool to be, and `Define` keeps one kind of operation.
51. `endpoint`: `Mount` returns an error, `endpoint: two tools are called <name>`, when two operations, state operations or page tools share a name, and mounts no `/mcp`; a caller that ignores the return value builds unchanged.
52. `cli`: `Client.Send` sends `Accept: application/json` on `GET` and `HEAD`, since a plain read reports no steps, and `Accept: text/event-stream` on every other method for the step stream, where it used to ask every request for the stream; a service that answers a `GET` with that header by opening a live subscription made every read through a shared cli, `api GET` included, hang. `Verb.Stream` declares that a Table verb streams and gives its command `--stream`, `cli.FlagStream`, as `api` has it too: the request sends `Accept: text/event-stream` without the client timeout and prints each frame as it arrives until the stream ends or is cancelled, `event: <name>` and the data through the cli's `Output`, or one `{"event","data"}` json line per frame under `--raw`, as hvrg prints them; a result frame with a failing status exits as that status. `Tools` leaves `--stream` out of every tool, so a tool call reads once and never opens the live stream.
53. `mcp`: a tool call over `/mcp` for a `GET` or `HEAD` operation reaches the service with `Accept: application/json`, the same rule as `cli.Client.Send`, so a read answers once and never opens a live subscription; every other method keeps `Accept: text/event-stream` and reports its steps as progress. A middleware that refuses such a read answers plain json, and the tool still answers its message and data.
54. `mcp`: an input that embeds `nimbody.Body` gets its record of the body keys on both transports, so `HasKey`, `HasValue`, `IsEmpty` and `Deny` answer alike on the route and the tool, an explicit `null` included. The route runs `Bound` on a non-empty body, as a handler does; a tool call runs `Bound` over the arguments as a JSON body, without the path, query and header inputs and without `fields`, `sort`, `jq`, `template`, `limit` and `cursor` unless the input declares them as body keys. An empty route body leaves the record empty, as before.
55. `mcp`: a raw body input, a `json.RawMessage` field tagged `body:"*"`. `Define` decodes no body for such an input and asks for no content type: the field stays empty on both transports and the service reads `ctx.Request().Body` itself, any JSON value, arrays and scalars included, capped with its own 413, after its own checks. A tool call sets the argument under the field's name, as raw JSON, as the request body the service reads, with `Content-Type: application/json`, and no body when the argument is absent. The field is required in the tool's input schema unless it is `omitempty`.
56. `mcp`: check order. With a raw body input nothing is decoded before the service runs, so the service answers its own 404, 409 or 403 before it reads the body. A structured body is bound before the service runs, as in v1.20.0: a malformed body answers 400, or `Spec.Invalid`, before the service can answer 404 for a missing id, on the route and on the tool.
57. `cli`: `OperationCommand` maps a raw body input to the standard body flags `--data '<json>'` and `--file <path|->`, and sends that body unwrapped, as given, any JSON value; there is no `--set` and no flag named after the input. A required raw body needs one of the two. `Body.Raw` is the mode: `Flags` adds only `--data` and `--file`, and `Get` answers the bytes as given, refuses anything that is not JSON and `--data` with `--file`, exit 2, and answers no body when neither is given.
58. `mcp`: `Answer[T]` is the output a service function returns to choose its success status per call: `Data`, `Status` and `Count`. The route answers `respond.JSON` with that status, `204` included, and the tool answers `structuredContent` `{data, status, count}`, as `respond.Rejection` chooses the status of an error; `Status` left at `0` is the operation's `Spec.Status`, so a create answers `201` when it inserts and `200` when the row already existed. The tool's `outputSchema` declares `status` and `count` beside `data`. An output that is not an `Answer` answers as before, `{data}` on the tool.
59. `mcp`: `Answer.Count` sets the envelope `count` on both transports, the route's `count` and the pagination total, and the tool's `count` and its rows hint, where a service answers a count that is not the computed one: the mappers of a sync run, `1` for an array, `0` on a list. Left `nil` it is the count `Define` computes, the rows of a `List`, the length of a slice or `1`, and an `Answer` over a `List` counts its rows.
60. `mcp`: an uploaded file input, a `File`, `*File` or `[]File` field tagged `file:"<part>"`, `File` being `name`, `content_type` and `content`. The route binds it from `multipart/form-data`, the part of that name with its file name and part content type, and the other body inputs from the form fields of their names, a value decoded as json where the field is not a string, and runs `Bound` over those fields; a json body binds the file as json, base64 content included. A tool call takes it as `{name, content_type, content}` with the content base64, since MCP carries no file. A content type left empty or `application/octet-stream` is sniffed from the content on both transports. `Spec.FileLimit` caps each file, `FileLimit`, 8 MiB, when left at `0`; a larger one answers `413` `<input> is larger than <limit> bytes` on the route and the same message as `isError` on the tool. The input schema describes the content as base64. This replaces item 50 for uploads: a multipart upload is an operation.
61. `mcp`: `Blob` is the output of an operation that answers bytes: `Content`, `ContentType`, `ETag` and `CacheControl`. The route answers the raw body with `Content-Type`, `Content-Length`, `ETag` and `Cache-Control`, and `304` when `If-None-Match` is the ETag. A tool call answers an `image/*` blob as an image block and any other as a `resource` block with `uri` `<server>://<path>`, `mimeType` and the base64 `blob`, without `structuredContent`; a blob over `Spec.FileLimit` answers `isError` `<name> answers <n> bytes, more than the <limit> a tool call carries`. An operation answering a `Blob` has no `outputSchema`. This replaces item 50 for blobs.
62. `mcp`: a raw body input takes a body that is not JSON on a tool call. The input declares the content type as a header input, `ContentType string` tagged `header:"Content-Type"`; a tool call that sets it to a type that is not `application/json` or `+json` and passes the body argument as a JSON string sends the string itself as the request body, `{"feed":"<rss/>","content_type":"application/rss+xml"}` sending `<rss/>` with that type. A call without the content type, with a JSON type, or with a body that is not a string sends the JSON as before. `cli.OperationCommand` gives such an input `--content-type`, and `Body.ContentType` sends a raw `--data` or `--file` as given with that type instead of refusing it as not JSON.
63. `cli`: `Call` takes the content type, `func(cmd, method, path, query, contentType, body)`, in the order `Send` does, so a `Call` hands it straight to `Client.Send`: `application/json` for the flags' body, the raw body's type, the multipart type, or empty with no body. `OperationCommand` maps a file input to `--upload <file>`, repeatable for a `[]File`, and a second file input to `--upload-<part>`; with an upload the other body flags are sent as form fields, json encoded where they are not strings, beside the file part, through the multipart writer `--upload` on `api` uses.
64. `mcp`: `Spec.Headers` declares header inputs that are no field of the input, `Header` with `Name`, `Param` and `Usage`, typed string and optional; a tool call sets each given one as a request header before `Spec.Middleware` runs, as a field tagged `header:` does. `state.Context.Headers` passes them to the `state`, `state_export` and `state_import` operations, so a service whose state access reads the app from a header, `{Name: "app_slug", Param: "SAuth-App-Slug"}`, answers a relayed state call that carries only a bearer token and the `app_slug` argument.
65. `cli`: the relay keeps the binary's own tools. `Relay` takes the local servers after `out`, and `MCPCommand` hands it the server it serves without a bridge: `tools/list` and `resources/list` answer the service's list with the local tools and resources it lacks appended, and a `tools/call` or `resources/read` of a name or uri only the local server holds runs locally as without the bridge, progress and the `steps` tool included. A name the service serves goes to the service; before the first list a call to a local name asks the service for its list once. `Relay` without local servers relays as before.
66. Breaking, minor bump: state is an ordinary API endpoint under `/api`. `GET /api/state` answers the schema, `POST /api/state/export` the records, files and images or a subset, and `POST /api/state/import` applies a file, with `dry_run`; `/state` at the root answers 404 and there is no path that serves it. `state.Register(host, middleware, groups...)` takes the service's `/api` chain and answers the three operations with it as `Spec.Middleware`, mounted with `mcp.Route` and run inside `/mcp` for the tools; it no longer takes a router, and `state.Context.Access` is gone. `endpoint.Set.APIMiddleware` is that chain: `Mount` routes the state operations under `endpoint.APIPath` with it, adds them to the mcp server and lists `/api/state` in `GET /status`; `endpoint.StatePath` is gone. `state.Path` is `/state` under the group, `state.GetDocument(service, version, groups...)` answers the schema document from the definitions without a request, `cli.PathState` is `/api/state`, and `cli.StateCommand` calls it there.
67. Breaking: the Terraform provider is a normal client provider. `terraform.Provider` takes the cli's `Client` and the state `Document` in code, from `state.GetDocument` or a schema generated at build and embedded, and no longer runs its own binary. The provider block takes `endpoint`, `client_id`, `client_secret`, `token` and `app_slug`, each else from the cli's environment, `<PREFIX>ENDPOINT` and the rest, with the credential order of the cli; a provider without an endpoint answers an error naming the variable. Read is an export by key, plan a dry run import, apply the import and delete the import's delete, all on `/api/state` through the service's chain. `<cli> terraform schema` writes the provider schema as `terraform providers schema -json` does, from the document in the binary with no endpoint and no login, for `tfplugindocs --providers-schema`. `cli.Settings.Put` sets a resolved value, and `cli.KeyToken` makes `EnvToken` read a token put there before `<PREFIX>TOKEN`.
68. Breaking: the self hosted registry is removed. `terraform/registry` is empty: no `/.well-known/terraform.json`, no `/terraform/providers/v1/`, `/terraform/modules/v1/` or `/terraform/state/` routes, no `Release` and `Token` hooks reading the GitHub release, no `SigningKey` served by the service, and no http state backend; `endpoint.Set.Terraform` is gone. Providers ship as signed GitHub release assets for the public registry and state lives in a normal backend. `terraform.GetFiles`, `GetModuleArchive`, `PutPackage`, `Package`, `Binary` and `Protocol` move from `terraform/registry` into `terraform`, and `<cli> terraform package` now also writes `terraform-provider-<type>_<version>_manifest.json` with protocol `6.0` and lists it in `SHA256SUMS`, the layout the public registry reads; the module tarballs stay. `golang.org/x/crypto` is indirect again.

Breaking, minor bump: `terraform.DefaultNamespace` is `nimling`, the GitHub account that owns the provider repositories on the public registry, so a provider without `Source` is `nimling/<name>`. `.github/workflows/terraform-provider.yml` is a reusable workflow that publishes the provider files and docs of a service release to `nimling/terraform-provider-<cli>`.
