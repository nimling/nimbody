# Changelog

## Unreleased

1. `state`: export and import of a service's data through `GET /state`, `POST /state/export` and `POST /state/import`: a schema document with field flags, NDJSON state lines with a manifest and a hash per group, export by filter and key, upsert, create and sync imports that map keys to ids and converge on a second run, deletes by key, dry runs, per record results over the step stream, and stored snapshots.
2. `cli`: `StateCommand` adds `state`, `state export` and `state import` to a cli and its mcp tools.
3. `state`: field flags are JSON pointers, `/config/client_secret`, found through nested `properties` and through `oneOf`/`anyOf` with a `discriminator`; `fields.sensitive`, `immutable` and `server_default` in `GET /state` now hold pointers where they held top level names. Export strips exactly the flagged pointers and never the object around them; immutable and server default checks on import work by pointer.
4. `state`: `Group.Discriminator` and `Group.Sensitive` declare the secrets of each type; `GET /state` publishes them as `fields.discriminator` and `fields.sensitive_by`, and export strips each record by its own type as well as by the schema flags.
5. `terraform`: every cli that registers it is its own Terraform provider. Started by Terraform it serves each state group as `<provider>_<group>`, with read by key, create and update as an upsert import, delete by key and a dry run in the plan; secrets are write only and sensitive per pointer and per type, immutable fields force replace, server defaults are optional and computed, and references are keys. `<cli> terraform install` places the binary in the local plugin directory or a filesystem mirror, at the cli's version.
6. `cli`: `Provider` and `EnvTerraform`, the hook `Execute` serves the provider through when `TF_PLUGIN_MAGIC_COOKIE` is set; `terraform` joins the tooling commands that are not mcp tools.
7. Module: `hashicorp/terraform-plugin-go` v0.30.0 and what it brings, grpc and protobuf among them, imported only by `terraform/`; `stretchr/testify` to v1.10.0 and `golang.org/x/net`, `crypto` and `text` raised by it.
8. `terraform/registry`: the running service is the Terraform registry of its own provider and modules. `Mount` serves `/.well-known/terraform.json`, the Provider Registry Protocol under `/terraform/providers/v1/samna/<cli>/` with versions, platforms, the download with its `SHA256SUMS`, signature and the org public key, and the Module Registry Protocol under `/terraform/modules/v1/samna/<module>/<system>/`, exactly at the version the instance runs. Files stream through the instance from the repo's GitHub release with the read token the host's `Release.Token` hook answers; a release that cannot be read answers 502.
9. `terraform/registry`: an optional http state backend at `/terraform/state/<workspace>` with `LOCK` and `UNLOCK`, 423 with the held lock on a conflict, behind the host's access middleware and over the host's storage callbacks.
10. `terraform`: `<cli> terraform package` writes the release files, a zip per platform, the `SHA256SUMS` to sign and a tar.gz per module in `deploy/terraform/<module>/<system>/`; the provider namespace defaults to `samna`.
11. `endpoint`: `Mount` with a `Set` mounts the common endpoint set, `/status`, `/status/health`, `/state`, `/mcp` and the Terraform registry, beside the service's own `/api`.
12. Module: `golang.org/x/crypto` is a direct requirement, for the test of the signed sums under `test/` only.
13. `cli`: `config set --config <name> key=value` creates a named config that does not exist yet, as the refusal's hint says; `Load` no longer refuses the unknown name for that one command, and every other command still refuses it with the same message and hint.
14. `respond`: a route declares the largest step stream frame it sends with `FrameLimitMiddleware(bytes)`, `0` for unbounded, and every stream announces it in the `X-Frame-Limit` header; a route that declares nothing announces `FrameLimit`, 16 MiB, as before. `stream.Read` sizes its line scanner from that header, so a result frame over 16 MiB no longer fails with `bufio.Scanner: token too long` where the route allows it. `POST /state/export` declares an unbounded frame, so a streamed export with blobs reads whole.
15. The step stream frame limit reaches the mcp path. `/mcp` announces `X-Frame-Limit` from the operation it calls, `stream.Scanner` is the one reader sized from that header, and the stdio bridge reads the service's `/mcp` stream through it, so a `state_export` result over 16 MiB passes `<cli> mcp`. The `state_export` tool declares the unbounded frame its route does. `mcp.Exec` reads the cli's own stderr without a fixed cap. The lines a host sends on stdin to `<cli> mcp` stay capped at 16 MiB, as no endpoint has answered when they are read.
16. `cli`: typed mcp tool input. A command tree whose root, or any command above a leaf, carries `AnnotationMCPInput: InputTyped` gets one input property per flag and per positional of the usage line, typed boolean, integer, number, string or array, with the required flags and positionals listed; an `id` positional is named for its parent, `article_id`. Without the annotation the tools keep the `{args, flags}` input as before, and a typed tool still accepts a call in that shape. `mcp.Flag` gains `Positional` and `Required`, `mcp.GetInputSchema` builds the typed schema.
17. `cli`: a flag a `Setting` marks `Secret`, or a flag annotated `AnnotationSecret`, never appears in a tool's input schema; `Settings.Flags` records the secret flags on the root.
18. `cli`: `PutOutput[Out]` declares a command's output struct. Its tool carries the `outputSchema`, `{data: <schema of Out>}` as `/mcp` tools do, and a stdio call answers `structuredContent` `{data: …}` from the json the command prints, unless the call shapes the result with `fields`, `sort`, `jq`, `template`, `raw`, `plain` or `format`. `mcp.GetOutputSchema` is the exported schema builder `Define` uses.
19. `mcp`: a destructive tool carries `_meta["anthropic/requiresUserInteraction"]: true`, `MetaUserInteraction`, on stdio and on `/mcp`; a tool's `_meta` is merged with its page link instead of replaced.
20. `mcp`: `Server.Instructions` is answered in `initialize`. `cli.MCPCommand` sends `GetInstructions(root, name)`, the root's `AnnotationMCPInstructions` or a few lines made from the root's `Short`.
21. `mcp`: `Spec.Example` is the example of an operation: `cli.OperationCommand` sets it as the command's `Example`, and the operation's tool appends it to its description through `Describe`, which caps a description at 4096 characters with the confirmation note.
22. `cli`: the credential store every api cli copied, on `Settings`: `GetCredential`, `GetCredentials`, `PutCredential`, `DeleteCredential` and `LockCredential` keep one login per host in `~/.<cli>/<host>.cred` and one machine token per host and client in `<host>_<client>.client`, with the keys the copies wrote, so a stored login carries over. The tokens live in the OS keychain through `Keychain`, `security` on macOS and `secret-tool` on Linux, with only the metadata and `<PREFIX>STORE=keychain` in the 0600 file; where no keychain answers they stay in the file. `LockCredential` is the cross process lock a refresh or an exchange holds.
23. `cli`: `Settings.Get(key)` answers a key's resolved value, a secret unmasked, from the layers `Load` read.
24. `cli`: `Client` is the shared api client and login. Its credential is `<PREFIX>TOKEN`, or `<PREFIX>ACCESS_TOKEN`, from the environment for CI, else the stored login, refreshed before expiry under the lock, else the machine pair `client_id` and `client_secret`, sent as Basic auth to the service on every request. A client whose service issues tokens sets `Exchange` to the path that does and exchanges the pair for a token instead, cached under the lock until 30 seconds before expiry, so parallel runs share one token, and exchanged again once when the service refuses it. `Send` is a `Send`: it reads the step stream, reports steps on stderr, names itself `<cli>/<version>` or `<cli>/<version> (mcp)`, and maps a status to the family exit codes with a hint.
25. `cli`: `Client.LoginCommand`, `LogoutCommand`, `StatusCommand` and `TokenCommand`: PKCE with a loopback callback, `--no-browser` with a pasted code, the session exchanged and refreshed at `TokenPath` and revoked at `RevokePath`, the identity from `IdentityPath` and the health from `HealthPath`, `/status/health` unless set. The cli names `LoginPath`, `TokenPath`, `RevokePath`, `IdentityPath` and `AppHeader` itself; nimbody carries no default for any of them, and `Client.Mount` and `login` refuse a client that leaves one out, naming each. `OpenBrowser` is the hook that opens the address.
26. `cli`: a default `Bridge`. `Client.Mount` validates the client, adds the four commands and, when the cli set no `Bridge`, makes `Client.Remote` the bridge: `<cli> mcp` relays to the service's `/mcp` with the stored credential when `GET /status` lists `/mcp` and the credential is a bearer token, and serves the tools locally otherwise, a Basic machine pair included.
27. `cli`: `Body` is the body flags every api cli copied: `--set key=value` repeated with dotted nesting and json values, `--data '<json>'`, `--file <path|->`, and `--upload <file>` for a multipart file part with the `--set` entries as form fields. `Body.Get` answers the bytes and the content type, and refuses `--data` with `--file` and a `--set` without `=`, exit 2.
28. `cli`: `APICommand(send, output)` is `api <method> <path>` with the body flags, for anything the resource table does not model. The method sets the command's access, so a `GET` is a read a protected config does not ask about; an unknown method or a path without a leading slash is refused, exit 2. `Client.Mount` adds it.
29. `cli`: `Table` builds the resource commands from a declaration: each `Resource` with its `Verbs` and `Children`, a verb's `Paths` indexed by how many ids it takes, `{name}` placeholders positional in path order unless `Fill` answers them, the access from the method unless `Access` says otherwise, the body flags where `Body` or `Upload` is set, and an `Example` per command, one line per arity, unless the verb sets its own. `Mount` adds every resource and a hidden top level shortcut for a child name used once.
30. `cli`: `Output.Format`, `--format concise|detailed`: concise keeps the leading scalar columns of a list, as the table picks them, and the scalar fields of an object; detailed, the default, keeps everything. `Output.Query`, `--query key=value` repeated, passes the server's own filters through `GetQuery`. A `--query` without `=` or another `--format` is refused, exit 2. Both flags come with `Root`; `Output.Flags` keeps its set, so a cli that defines `--query` itself still starts.
31. `cli`: `config get` and `config list` print json when the command's `--json` flag is set, on a terminal too.
32. `cli`: `HelpCommand(banner, document)` is the shared `help`: with no topic it prints the bundled SKILL.md without its frontmatter to stdout, headings styled and the banner first only on a terminal; `help <command>` is that command's help, an unknown one exit 2. `HelpFunc(banner, base)` prints the banner above the root's help only on a terminal.
33. `cli`: `Root(root, settings, output)` mounts `Settings` and `Output` on the root, with `--format` and `--query`, typed mcp input, silenced cobra errors, and a `PersistentPreRunE` that loads the settings and guards the write before the cli's own hook, so a cli cannot skip either.
34. `cli`: `Root` refuses a `Setting` that is `Secret` and names a `Flag`, at start, since a secret is never a flag; `Settings.Flags` alone still takes one, so a cli that has not moved to `Root` keeps its flag.
35. `cli`: `--plan` stops `config set`, `config use`, `config init` and `config local` too: each prints the write it would make, a secret masked, and exits 0 without touching a file.
36. `cli`: the `config set` example writes a named config with `--to`.
37. `cli`: `CompletionCommand(root, skill)` is the shared `completion [shell]`: it prints the script for one shell, or with `--auto` detects the shell from `$SHELL`, writes the script under the XDG data dir, `$XDG_DATA_HOME/<cli>/completions` or `~/.local/share/<cli>/completions`, and keeps one managed block in `~/.zshrc` or `~/.bashrc`; fish gets its own completions directory. `--skill` installs the bundled skill in the same step. It turns off cobra's default completion command. `GetDataDir` answers the data dir.
38. `cli`: `cli.Version` is the one ldflags symbol, `-X github.com/nimling/nimbody/cli.Version=v1.2.3`; `GetVersion` answers it, or the module version a `go install …@version` build carries, or `dev`.
39. `cli`: `VersionCommand(server)` prints `{version, server}`, the server's from the function given, `Client.GetServerVersion` reading `GET /status` for an api cli and nil for a tool cli; an unreachable server is a warning on stderr, never a failure.
40. `cli`: `Notifier` is the update notifier. `Mount` checks `Latest` at most once per `Every`, a day by default, cached in `~/.<cli>/update.json`, and prints a note on stderr after the command when a newer version is out, only on a terminal and never under mcp or for a `dev` build. `<PREFIX>NO_UPDATE_NOTIFIER` turns it off. `Newer` compares two versions, a release above its prerelease.
41. `cli`: `--set key=@path` reads the value from a file, then decodes it as json when it parses, as every other `--set` value; in a multipart upload the file's content becomes the form field. An unreadable file is rejected.

## v1.0.0

The first public release.

1. `nimbody`: request body binding that records which keys were sent, for partial updates, with `HasKey`, `HasValue`, `ForObject`, `Deny`, `IsEmpty` and `GetUnknown`.
2. `query`: validation of query parameters, pagination and cursors.
3. `respond`: one response envelope with data, error, pagination and request id, and a step stream over server sent events that ends in a result frame.
4. `cli`: the shared command line layer: exit codes, output as table, plain text or json (json when piped), output templates, named configs with a local override, env files and a write guard, and install commands for a Claude Code plugin and skill.
5. `mcp`: every command served as an mcp tool over stdio and streamable http, with tool annotations, inline images and an MCP App page.
6. `stream`: a loopback login page for clis and the client for the step stream.
